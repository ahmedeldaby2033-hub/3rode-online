# خطة تحسين محركات البحث (SEO) — عروض أونلاين 3rde.online

> أولوية قصوى للمستخدم (2026-11-19): جلب الزيارات من **جميع** محركات البحث،
> والموقع يجب أن يكون صديقاً لمحركات البحث **بدون أي مشاكل**.
> هذه الخطة ملزمة للبناء: كل بند فيها يُنفَّذ، ويُختبَر قبل التسليم.

## 1) المبدأ الأساسي: صفحات HTML ثابتة (Static)

- الموقع يُبنى **بتوليد صفحات HTML كاملة على الخادم وقت المزامنة** (Static Site
  Generation)، وليس تطبيقاً يعتمد على JavaScript لعرض المحتوى.
- السبب: محركات البحث تقرأ HTML مباشرة. أي محتوى يظهر فقط بعد تنفيذ
  JavaScript قد لا يُفهرس أو يتأخر فهرسته، وهذا هو الخطأ الأول في مواقع
  المقارنة.
- كل منتج وكل ماركة وكل دليل شراء وكل مقال = **صفحة HTML مستقلة برابط
  خاص**، موجودة على الاستضافة قبل أن يزورها أي محرك بحث.

## 2) الروابط (URLs)

- روابط نظيفة وقصيرة، بالإنجليزية (أفضل للفهرسة والمشاركة)، مثال:
  - الصفحة الرئيسية: `https://3rde.online/`
  - صفحة منتج: `https://3rde.online/mobiles/oppo-a6/`
  - صفحة ماركة: `https://3rde.online/brand/samsung/`
  - دليل شراء: `https://3rde.online/guides/best-phones-under-10000/`
  - كوبونات: `https://3rde.online/coupons/`
  - مقارنة: `https://3rde.online/compare/?m=oppo-a6,samsung-a16` (لا تُفهرس)
- **صفحة واحدة لكل موديل**: العروض المكررة لنفس الموديل تظهر داخل صفحة
  الموديل الواحدة، ولا تُنشأ صفحة لكل عرض (تجنّب المحتوى المكرر).
- لا معلمات (parameters) في روابط الصفحات المفهرسة. روابط الفلاتر والبحث
  والترتيب لا تُفهرس (انظر قسم `robots.txt`).

## 3) خريطة الموقع وملف robots

- `sitemap.xml` يُولَّد تلقائياً مع كل مزامنة، ويشمل: كل المنتجات، كل
  الماركات، كل أدلة الشراء والمقالات، صفحة الكوبونات، الصفحات الثابتة.
  كل رابط فيه `lastmod` = تاريخ آخر تحديث فعلي للصفحة من الشيت.
- `robots.txt`:
  - السماح الكامل للزاحفين.
  - منع فهرسة: `/admin/`، `/search/`، `/compare/`، روابط الفلاتر والترتيب.
  - الإشارة إلى `sitemap.xml`.
- بعد النشر مباشرة: إرسال خريطة الموقع إلى:
  - **Google Search Console** (جوجل — المصدر الأول للزيارات في مصر).
  - **Bing Webmaster Tools** (بينج — وفهرسه يغذي: Yahoo وDuckDuckGo
    وEcosia، أي أن إرسالاً واحداً يغطي كل محركات البحث الأخرى).
- التحقق من الملكية في الأداتين بملف HTML أو وسم meta، من لوحة التحكم.

## 4) البيانات المنظمة Schema.org (الأهم لظهور الأسعار في نتائج البحث)

كل صفحة منتج تحمل JSON-LD:

- `Product` (الاسم، الصورة، الوصف، الماركة، التقييم `aggregateRating`).
- `Offer` / `AggregateOffer` (أقل سعر `lowPrice`، أعلى سعر `highPrice`،
  العملة `EGP`، التوفر `InStock`/`OutOfStock`، رابط العرض `url`).
- `BreadcrumbList` (الرئيسية › الهواتف › Samsung › الموديل).
- `FAQPage` (أسئلة الصفحة المولّدة من المواصفات).
- صفحات الأدلة والمقالات: `Article` + `FAQPage`.
- كل الصفحات: `Organization` (الاسم، الشعار، الرابط) و`WebSite` مع
  `SearchAction` (حتى يظهر مربع بحث الموقع داخل نتائج جوجل).
- **التحقق قبل التسليم** بأداة Rich Results Test من جوجل على عينة صفحات،
  وإصلاح أي خطأ فيها. بيانات الأسعار في Schema يجب أن تطابق السعر الظاهر
  في الصفحة تماماً (أي اختلاف = مخالفة قد تُفقد الظهور الغني).

## 5) وسوم Meta لكل صفحة

- `title` فريد لكل صفحة، بصيغة ثابتة، مثال:
  - منتج: `سعر OPPO A6 في مصر 2026 — قارن بين جوميا وأمازون ونون | عروض أونلاين`
  - ماركة: `أسعار هواتف Samsung في مصر — عروض أونلاين`
- `meta description` فريدة لكل صفحة، تتضمن السعر الحالي وأرخص متجر.
- Open Graph + Twitter Cards (الصورة، العنوان، الوصف) حتى تظهر بطاقات
  جميلة عند المشاركة على فيسبوك وواتساب وتليجرام.
- `lang="ar" dir="rtl"` في كل صفحة، مع `hreflang="ar-eg"` (الجمهور: مصر).
- `canonical` في كل صفحة يشير إلى رابطها الرسمي (يمنع مشاكل المحتوى
  المكرر بين روابط المنتج المختلفة).

## 6) المحتوى الفريد (تجنّب عقوبة المحتوى المكرر)

- كل صفحة منتج لها وصف فريد مولّد من بيانات الشيت: المواصفات الكاملة،
  المميزات، العيوب، تقييم موبيزل، فرق السعر بين العروض، تاريخ الأسعار.
- لا نسخ لوصف المتجر حرفياً. لا صفحات فارغة أو شبه فارغة.
- صفحات "أفضل هاتف لـ..." وأدلة الشراء تُولَّد من بيانات الأسعار الحالية،
  وتُحدَّث تلقائياً عند تغير الأسعار، مع تاريخ تحديث ظاهر.
- روابط داخلية قوية: من كل منتج إلى منتجات مشابهة، وإلى صفحة الماركة،
  وإلى دليل الشراء المناسب، ومن كل دليل إلى المنتجات المذكورة فيه.

## 7) الصور

- كل الصور على الاستضافة (ليست روابط خارجية)، بصيغة WebP، مع نسخة
  احتياطية JPEG.
- `alt` لكل صورة = اسم المنتج الكامل (مثال: `هاتف OPPO A6 أزرق ياقوتي
  128 جيجا`).
- تحميل كسول (lazy loading) للصور أسفل الصفحة، وعرض/ارتفاع ثابتان لمنع
  اهتزاز التخطيط (CLS).
- العلامة المائية (الشكل ب) على الصور الرئيسية فقط، وليس على المصغرات.

## 8) السرعة وتجربة الهاتف (Core Web Vitals)

- الهدف: LCP أقل من 2.5 ثانية، CLS أقل من 0.1، INP أقل من 200 مللي ثانية.
- الوسائل: HTML ثابت، CSS مضغوط، JavaScript قليل ومؤجل، صور WebP
  محلية، خطوط نظام أو خط واحد مضغوط، تخزين مؤقت (caching) للملفات
  الثابتة.
- التصميم متجاوب أولاً للهاتف (أغلب الزوار من الهاتف)، واختباره على
  شاشات صغيرة.
- الاختبار قبل التسليم: PageSpeed Insights (جوجل) على الرئيسية وعينة
  منتج، وإصلاح أي درجة حمراء.

## 9) الإعلانات والـ SEO معاً

- إعلانات أدسنس **لا** تُحمَّل قبل المحتوى، ولا تدفع المحتوى أثناء التحميل
  (CLS). مواضع الإعلانات محجوزة بارتفاع ثابت.
- لا إعلانات منبثقة (popups) تغطي المحتوى، ولا إعلانات بينية إجبارية —
  هذه مخالفات تؤثر على الترتيب وعلى قبول أدسنس.
- بانر موافقة ملفات تعريف الارتباط (Cookie consent) يظهر أسفل الصفحة
  ولا يحجب المحتوى.

## 10) ما بعد النشر (تشغيل مستمر، من لوحة التحكم)

- Search Console + Bing Webmaster: مراقبة الأخطاء والفهرسة أسبوعياً.
- سجل المزامنة يحدّث `lastmod` في خريطة الموقع مع كل تغيير سعر.
- أي منتج يُحذف من الشيت: صفحته تتحول إلى صفحة "المنتج غير متوفر"
  مع اقتراح بدائل، أو إعادة توجيه 301 إلى بديل — **لا صفحات 404
  لمنتجات كانت مفهرسة**.
- لا شراء روابط، ولا كلمات مفتاحية مخفية، ولا محتوى مولّد بلا قيمة —
  كلها طرق تؤدي إلى عقوبات.

## 11) قائمة التحقق قبل التسليم

- [ ] عينة 5 صفحات منتجات تجتاز Rich Results Test بلا أخطاء.
- [ ] `sitemap.xml` و`robots.txt` موجودان ويعملان.
- [ ] PageSpeed Insights أخضر على الهاتف للرئيسية وعينة منتج.
- [ ] لا صفحة مفهرسة بلا محتوى، ولا روابط مكسورة داخلية.
- [ ] صفحات السياسات الست موجودة ومربوطة من التذييل (انظر
      `docs/legal-pages.md`).
